# AI Interactions — Multi-Step Reasoning Traces

This project's recommender is an **agent** that reasons in multiple steps. For
each request it runs a **PLAN → ACT → CHECK → FIX** decision chain, and at each
step it **calls a named tool** (see [src/tools.py](src/tools.py)), reads back the
result, and decides what to do next — the same shape as an LLM agent emitting
tool-calls and reading observations.

- **Where the chain lives:** [src/agent.py](src/agent.py) (`AgenticRecommender.run`).
  Each link is recorded as a `ReasoningStep` (`thought → tool call → observation
  → decision`).
- **Tools the agent can call:** [src/tools.py](src/tools.py) —
  `catalog_stats`, `validate_energy`, `detect_preference_conflict`, `count_genres`,
  plus `recommend_songs` (the ACT tool).
- **Full committed log:** [logs/agent_trace.md](logs/agent_trace.md) — the
  complete, verbatim reasoning chain for four representative requests.

### Regenerate the traces

```bash
# One request, written to any path:
python3 -m src.main --trace-out logs/agent_trace.md

# The full four-request log embedded below is regenerated by the snippet in
# "How the log is produced" at the bottom of this file.
```

## Embedded highlights

The excerpts below are copied directly from [logs/agent_trace.md](logs/agent_trace.md).

### 1. A tool-call decision chain (clean request)

Request: `pop / happy / energy 0.8`. The agent inspects the catalog, validates
the energy, checks for contradictions, scores, and grades its own output — five
tool-backed steps, no fixes needed.

```
Step 1 — PLAN   catalog_stats({'n': 17})            -> 17 songs, 14 genres
Step 2 — PLAN   validate_energy(0.8)                -> valid; no change
Step 3 — PLAN   detect_preference_conflict(...)     -> no conflict
Step 4 — ACT    recommend_songs(k=4, penalty=0.0)   -> top_score 9.03
Step 5 — CHECK  count_genres(...)                   -> {'pop':2,'indie pop':1,'metal':1} -> PASSED
```

### 2. The agent catches and fixes its own mistake (decision chain with a loop)

Request: `lofi / chill / energy 0.4`, k=5. CHECK finds three `lofi` tracks,
FIX raises the diversity penalty, and the agent **re-runs ACT/CHECK** until the
shortlist passes. This is the multi-step reasoning changing the output.

```
Step 4 — ACT    recommend_songs(k=5, penalty=0.0)   -> top_score 8.28
Step 5 — CHECK  count_genres(...)                   -> {'lofi':3,...}  ISSUE: lofi 3x (>2)
Step 6 — FIX    (decision)                           -> raised diversity_penalty to 1.5
Step 7 — ACT    recommend_songs(k=5, penalty=1.5)   -> top_score 8.28
Step 8 — CHECK  count_genres(...)                   -> {'lofi':2,'ambient':1,'r&b':1,'reggae':1} -> PASSED
```

### 3. A tool drives a guardrail (bad input)

Request: `energy 5.0` (out of the 0–1 range). The `validate_energy` tool clamps
the value and the observation feeds a recorded decision — no crash.

```
Step 2 — PLAN   validate_energy(5.0)   -> {'value':1.0,'changed':True,
                                           'message':'energy 5.0 out of range; clamped to 1.0'}
                Decision: energy 5.0 out of range; clamped to 1.0
```

### 4. A tool drives a strategy change (conflicting request)

Request: `rock / sad / energy 0.9`. The `detect_preference_conflict` tool reports
that a sad mood contradicts high energy, so the agent softens the mood weight
before it even scores.

```
Step 3 — PLAN   detect_preference_conflict(...)
                -> {'conflict':True,'reason':"mood 'sad' usually implies low energy,
                    but energy=0.9 is high"}
                Decision: Softened mood weight by 25% (weights m: 3.0 -> 2.2)
```

## How the log is produced

The committed log is generated by running the agent over four requests and
calling `write_trace`:

```python
from src.agent import AgenticRecommender, write_trace
from src.recommender import load_songs

songs = load_songs("data/songs.csv")
runs = [
    ("Request A: pop / happy / energy 0.8 (clean pass)",
     AgenticRecommender(songs, k=4).run({"genre": "pop", "mood": "happy", "energy": 0.8})),
    ("Request B: lofi / chill / energy 0.4 (diversity self-correction)",
     AgenticRecommender(songs, k=5).run({"genre": "lofi", "mood": "chill", "energy": 0.4})),
    ("Request C: pop / happy / energy 5.0 (out-of-range guardrail)",
     AgenticRecommender(songs, k=3).run({"genre": "pop", "mood": "happy", "energy": 5.0})),
    ("Request D: rock / sad / energy 0.9 (conflict detection)",
     AgenticRecommender(songs, k=4).run({"genre": "rock", "mood": "sad", "energy": 0.9})),
]
write_trace(runs, "logs/agent_trace.md")
```

Every step in [logs/agent_trace.md](logs/agent_trace.md) is real program output,
not hand-written.
